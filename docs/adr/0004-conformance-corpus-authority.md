# ADR 0004: Conformance goldens come only from the pinned, repo-built oracle; the corpus is the published contract

- Status: Accepted
- Date: 2026-07-02

## Context

The `/conformance` corpus (208 cases, ~560 golden files) is the
machine-checkable definition of correct behavior across tiers and — by design
— across future language bindings. Its authority depends entirely on **where
golden bytes come from**. Three hazards were live:

- Goldens were generated by whatever `yanglint` was reachable, with no check
  against the `/VERSIONS` engine pin — a stray system binary could silently
  rewrite the corpus with different semantics (GAP F-010).
- Two divergent generation implementations existed (`conformance-tool.py`'s
  own yanglint invocation vs `conformance_lib.py`'s), with different flags
  and no op-type/with-defaults support in one of them.
- The experimental `datatree` engine needed a machine floor for its
  path-to-stable, and the roadmap keeps the corpus language-neutral so a peer
  binding can attach — both require the corpus to be consumable and trusted.

## Decision

1. **Single generation path.** `conformance_lib.write_goldens` is the only
   code that writes golden bytes; `conformance-tool.py gen`/`add` delegate to
   it. Cases with no yanglint-comparable golden (compile-only `schema-ir`
   tier, helper-only formats) are skipped explicitly, never guessed.
2. **Oracle identity is part of the golden contract.** Generation probes the
   **repo-built** oracle at `go/internal/libyang/.build/libyang-install/bin/yanglint`
   — the binary generation actually invokes — and refuses to write if its
   version differs from the `/VERSIONS` pin. There is deliberately **no
   override flag**: the only bypass is editing `/VERSIONS` in a reviewed
   diff, which is exactly the event that must re-run the full corpus.
3. **The differential lane is datatree's graduation gate.** A case opts in
   with `datatree = true`; `cmd/cambium datatree-diff` runs every flagged
   case through both engines and byte-compares after **compact-only**
   normalization (whitespace/`json.Compact` only — element and member order
   is never normalized away, because order is the product).
4. **The corpus ships as a versioned artifact** (`scripts/package-conformance.py`
   plus the `conformance-artifact` workflow, with sha256), so an external
   implementation can consume fixtures+goldens+manifest+`/VERSIONS` without
   cloning the repo. See the
   [conformance artifact guide](../guides/conformance-artifact.md).

## Consequences

- Byte-identical regeneration is provable and was proven: regenerating all
  data-case goldens through the consolidated path leaves the tree clean.
- Oracle drift fails loudly *before* any byte is written; a VERSIONS bump
  without an engine rebuild is caught by the same probe.
- `datatree = true` is an honest, per-case capability claim; the lane fails
  if either engine regresses, and every new opt-in is gated automatically.
- Peer bindings get a consumable, versioned contract instead of a repo-shaped
  convention.

## Reversal cost

Effectively unrecoverable trust. Relaxing the pin or adding a bypass flag
re-opens silent corpus rewrite: one drifted regeneration landing in a large
diff would redefine "correct" for every tier and binding at once, and
detecting it after the fact requires re-deriving 560 files against a
reconstructed oracle. Superseding this ADR should require a replacement
authority mechanism of at least equal strength.

## Alternatives considered

- **Probe the PATH `yanglint`** — rejected (and reverted during review): it
  guards a binary generation does not use, and crashes in the canonical
  no-system-yanglint setup.
- **Order-insensitive differential comparison** — rejected: normalizing
  element/member order away would make the lane blind to the exact class of
  bug the project exists to prevent.
- **Manual "regen carefully" convention** — rejected: the corpus is too large
  for eyeball review of semantic drift; the gate must be mechanical.
